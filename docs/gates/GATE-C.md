# Gate C — отказоустойчивость и изоляция ошибок

**Состояние Gate и его дата содержатся только в [CURRENT-STATE](../CURRENT-STATE.md#3-gates).** Offline pass и реальный отказ — разные доказательства.

## Критерии

1. Подтвердить, что отказ LLM, HA-MCP, Telegram, сети или отдельного запроса **не** разрешает обход deterministic policy.
2. При недоступном источнике device state/registry: fail-closed, без неизвестных/повторных физических команд.
3. Проверить дедупликацию, сроки подтверждения, отмену и отсутствие replay после ошибки/перезапуска.
4. Проверить наблюдаемость без утечки токенов, приватных URL и данных домашней сети.
5. Выполнять настоящие fault/recovery тесты только по отдельному плану и разрешению; не трогать HA Green и production в рамках документации.

## Что не доказывает готовность

- Green offline tests или STAGE mock не равны live HA fault isolation.
- `NEW_LIGHT_REVIEW=partial` при десяти `unavailable` — результат чтения, сам по себе не подтверждает обработку отказов в физическом dispatch.
