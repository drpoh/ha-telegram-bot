## Log-driven reliability fixes (2026-10-16)

- DEV journal revealed a 90-second Telegram polling timeout terminating the Node process (systemd restarted it).
- DEV Telegram now registers an error handler for Telegraf update processing and catches launch/polling promise rejection. This is not yet proof that every long-polling timeout is recoverable; verify during a controlled fault test.
- AI router no longer calls unconfigured OpenRouter (avoids replacing a Gemini 503 with a missing-key error).
- MCP result logging now reports summaries rather than full device lists (other verbose request paths remain to audit).
- Prompt keeps device type and room in sensor battery queries and rejects unrelated search results; this is a prompt-level quality fix, not a deterministic resolver.
- Added battery-search prompt regression test.
- Validation on Pi pending one combined offline regression and DEV Telegram acceptance cycle; production V2 untouched.
